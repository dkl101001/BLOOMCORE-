## No center-drop rule

A derivative, summary, fork, audit, or publication must not retain terminology while dropping the governing center.

Center-drop includes:

- calling ECA a generic coherence engine without preserving the elemental atlas role;
- treating BLOOMCORE as metaphor instead of field-law/accountability infrastructure;
- treating anti-coercion as optional rather than binding;
- preserving names while reversing or blurring authorship;
- translating private lineage into generic symbolic language without custody notes;
- removing receipts while keeping claims.

## Versioning requirements

Every public release or derivative should include:

- version number;
- release date;
- author or maintainer identity;
- upstream source reference;
- list of changes;
- public/private boundary statement;
- known limitations;
- anti-inversion compliance note.

## Receipt requirements

Major claims should be paired with receipts where possible:

- source file path;
- commit hash or archive hash;
- timestamp;
- line reference or section reference;
- change rationale;
- validation state: OPEN, HOLD, or REJECT.
